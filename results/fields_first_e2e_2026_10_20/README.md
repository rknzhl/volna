# Перенос между окнами: конечная реализация

Реализация схемы [PDF](../../research/phase_ssa_method.pdf) по конечным показаниям датчиков. Начальные круговые координаты и регрессионный декодер Фурье не используются; обратное восстановление выполняется интегрированием оценённых полей методом RK4.

[Инфографика пайплайна](../../research/figures/fields_first_pipeline_overview_v2.png).

## Алгоритм

Вход $Y\in\mathbb R^{N\times m}$: строки — моменты времени, столбцы — датчики. $L$ — длина окна, $K$ — число полных окон после обрезки краёв, $D$ — сохранённая линейная размерность, $r$ — число фаз.

| Шаг | Пространства и вычисление |
|---|---|
| 1. Подготовка окон | MSSA и фиксированный фильтр выделяют остаток и медленную компоненту. Из нормированного по датчикам остатка строятся окна $x_i\in\mathbb R^{mL}$ и координаты $\xi_i=U^\top x_i\in\mathbb R^D$, $U\in\mathbb R^{mL\times D}$. |
| 2. Касательные пространства | Оцениваются ортонормированные базисы $Q_i\in\mathbb R^{D\times r}$. Число $r$ выбирается по устойчивым классам $H_1$: равенство $r=b_1$ используется **при предположении тора**. Углы на этом шаге не строятся. |
| 3. Перенос | $J_i=P_0UQ_{i+1}$, $A_i=(J_i^\top J_i)^{-1}J_i^\top P_1UQ_i\in\mathbb R^{r\times r}$. $P_0$ удаляет последний снимок полного окна, $P_1$ — первый. Проверяется полный столбцовый ранг $J_i$. |
| 4. Базис и двойственная форма | Гладкое поле $W_i=Q_iR_i\in\mathbb R^{D\times r}$ оценивается из $R_{i+1}\approx A_iR_i$, $R_0=I_r$, $R_i\in\mathbb R^{r\times r}$, с регуляризацией. $\beta_i=(W_i^\top W_i)^{-1}W_i^\top\in\mathbb R^{r\times D}$. |
| 5. Полные периоды | **После $W$** проверяются целые коциклы $c_{uv}\in\mathbb Z^r$, составляющие полный примитивный базис когомологий конечного комплекса. Интегралы $\beta$ аппроксимируются на путях и проецируются на замкнутые коцепи: $b_{uv}\approx f_v-f_u+\Pi c_{uv}$, $b_{uv},f_v\in\mathbb R^r$, $f_0=0$, $\Pi\in\mathbb R^{r\times r}$. |
| 6. Углы | Из $2\pi\Pi^{-1}f_v$, целых переходов между картами и локальных производных $\Pi^{-1}\beta$ строится гладкая аппроксимация $\Phi(\xi)\in\mathbb T^r$; опорному окну назначается нуль. |
| 7. Обратное восстановление | $E_j(\xi)=W(\xi)\Pi e_j/(2\pi)$, где $e_j\in\mathbb R^r$ — $j$-й единичный вектор. Из опорного окна последовательно решаются $\dot\xi=E_j(\xi)$ до нужного угла. После возврата через $U$ и обратного масштабирования перекрытия усредняются. Медленная компонента наблюдаемого блока добавляется обратно. |

Конечные изменения относительно точной конструкции: фильтрация, отсечение линейного пространства на относительном уровне $10^{-10}$, оценка касательных пространств, регуляризованная оценка $W$, квадратура, проекция на замкнутые коцепи и гладкое продолжение фаз. Ни одно из них не имеет здесь общей гарантии сохранения всех фаз.

Проверяются замкнутость, двойственность $D\Phi E\approx I_r$, постоянство фазового шага, обратное восстановление, возвращение за $2\pi$, порядок потоков и область их применимости. Примитивность сертифицируется **для конечного комплекса**; принятие по численным порогам не доказывает глобальную обратимость истинного многообразия.

## Запуск

Из корня репозитория. CSV содержит числовые показания; столбец времени задаётся явно и должен иметь равномерный шаг. Пропуски не интерполируются. Также поддерживаются TSV, NPY и NPZ.

Проверенные версии зависимостей: [requirements-fields-first.txt](../../code/lag_ssa/requirements-fields-first.txt). Основной API: `SensorPipeline().fit(Y_train)`, затем `.transform(Y_query, start_index=...)` в [fields_first_sensor_pipeline.py](../../code/lag_ssa/fields_first_sensor_pipeline.py).

```bash
nice -n 15 .venv/bin/python code/lag_ssa/run_fields_first_sensor.py \
  path/to/sensors.csv --time-column time --train-count 1800 \
  --threads 1 --output results/my_sensor_fit
```

Проверка с шумом:

```bash
nice -n 15 .venv/bin/python code/lag_ssa/benchmark_fields_first_sensors.py \
  --case fundamental2waves --trend quadratic --noise 0.05 \
  --ntrain 2400 --ntest 600 --seed 31 --threads 1 --max-candidates 3 \
  --output results/fields_first_e2e_2026_10_20/fundamental2waves_noise0p05.json
```

По умолчанию используется один вычислительный поток. Опция --max-candidates ограничивает число попыток; исчерпание бюджета даёт статус unresolved. Текущая обёртка ограничивает $mL\le128$. Запуск на CSV сохраняет fit.json, transform.json и, при успешном преобразовании, reconstruction.npz с фазами, восстановленными показаниями и временными индексами.

## Область результата

Восстанавливаются показания **тех же датчиков по новому наблюдаемому блоку**. Это не прогноз и не восстановление поля в новых пространственных точках. Медленная компонента берётся из наблюдений, а не идентифицируется как физический тренд; малая общая ошибка не подтверждает восстановление каждой фазы. Произвольные датчики, поля и уровни шума не покрываются общей гарантией.

## Происхождение сохранённых файлов

[previous_results/](previous_results/) содержит запуски scratch-версии до упаковки. В текущем коде добавлены две проверки нового блока: конечность диагностик и ошибка обратного восстановления окон. Сохранённые ошибки удовлетворяют текущим порогам, но эти файлы не являются повторным запуском текущей версии.

## Численные результаты

Шум — стандартное отклонение независимой гауссовской добавки относительно стандартного отклонения чистых колебаний каждого датчика. RMSE нормирована на эту же величину, без постоянного фона и тренда в знаменателе. На отложенный блок выделено 600 отсчётов; после обрезки фильтров оцениваются 410. Генератор и его фазы используются только после выбора модели и восстановления.

| Пример | Шум | RMSE показаний | Только фильтрация | MAE фаз, рад |
|---|---:|---:|---:|---:|
| Один нелинейный датчик, линейный тренд | 1% | 1.28% | 0.62% | 0.0051 |
| Один нелинейный датчик, линейный тренд | 5% | 1.25% | 1.71% | 0.0047 |
| [12 датчиков двух волн, квадратичный тренд](fundamental2waves_noise0p05.json) | 5% | 0.89% | 0.64% | 0.0048 |
| [Оптический пример: слоистая среда, установившийся режим, линейный тренд](opticalsteady1d_layered_noise0p05.json) | 5% | 1.13% | 0.63% | 0.0054 |
| [Три нелинейных датчика, другие частоты и начальные фазы, квадратичный тренд](nonlinear3sensor_wide_noise0p05.json) | 5% | 2.73% | 2.05% | 0.0173 |

Первые две строки — предыдущие запуски в `previous_results/`, до упаковки кода. Новые проверки также удовлетворены сохранёнными диагностическими значениями; повторное обучение не проводилось.

Во всех строках восстановлено правильное число фаз; найденные целые матрицы сопоставления имеют модуль определителя 1. Окна восстановлены **потоками оценённых полей**. Входные частоты, фазы генератора и регрессионный декодер в обучение не подставлялись. Параметры выбирались по обучающим проверкам, без истинных фаз.

Эти результаты поддерживают восстановление фаз на проверенных примерах. Преимущество над одной фильтрацией по точности показаний не установлено: в нескольких строках фильтрация точнее. Это отдельный вопрос от получения фаз и обратного отображения через поля.

[При шуме 10%](scalarcircle_noise0p10.json) скалярный пример не принят в пределах 12 попыток: окна длины 4, 8, 16 и 32, по три размера окрестности. Среди вычисленных полных оборотов минимальный дефект возврата — 9.74% при пороге 5%. Поиск завершён по бюджету; это не утверждение о невозможности восстановления при других параметрах.

[Контроль с меняющейся частотой](scalarcircle_chirp_noise0p01.json) также не принят: три окрестности при длине окна 4. В лучшей из этих попыток отклонение фазового шага от постоянного — 0.061 рад при пороге 0.05. Этот сигнал нарушает предположение постоянного сдвига фаз.

Все новые запуски выполнялись последовательно, с одним потоком BLAS/OpenMP и приоритетом `nice +15`. [Проверка упаковки](packaging_and_safety_checks.json): новая формула вычисления полей и формы совпадает с прежней до округления; шесть проверок отказов и восстановления пройдены. [Окружение](environment.json) фиксирует версии библиотек.
